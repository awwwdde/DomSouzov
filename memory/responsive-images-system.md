Оптимизация картинок сайта (2026-07-30). Оригиналы загрузок — до 6000×4000, раньше отдавались как есть и тормозили скролл.

**Бэкенд** (`backend/main.py`, `serve_upload`): `/uploads/{file}?w=<ширина>` отдаёт уменьшенную копию (только вниз, апскейла нет). Ширина «снапится» к набору `_RESIZE_WIDTHS` (320…1920). При `Accept: image/webp` отдаёт WebP. Работает и из БД, и с диска (`_build_resized`). Кэш — `lru_cache` в памяти процесса (содержимое /uploads неизменяемо). Требует Pillow (уже в requirements).

**Фронтенд** (`frontend/src/lib/img.ts`): `imgAttrs(src, sizes, fallbackWidth)` → `{src, srcSet, sizes}`. Спредить в `<img>`/`<motion.img>` вместо `src=`. Трогает только свои растровые загрузки (относительные *.jpg/png/webp), внешние/svg/data: пропускает. Уже применён во всех публичных страницах/компонентах с картинками (кроме логотипов Header/Footer).

**Как применять в новом коде:** для любой новой картинки из загрузок — `<img {...imgAttrs(url, sizes, fallback)} .../>`, где `sizes` описывает ширину слота (напр. `'(min-width:1024px) 33vw, 100vw'`).
